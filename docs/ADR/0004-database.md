# ADR-0004. Drizzle и миграции вместо `CREATE TABLE IF NOT EXISTS`

**Статус:** принято, 8 сентября 2026.

## Контекст
Сейчас: драйвер `pg` напрямую, схема создаётся функцией `initDb()`
через `CREATE TABLE IF NOT EXISTS` при старте. Это значит: изменение
схемы — ручная операция на проде, отката нет, история изменений
нигде не записана. Появляются заказы серверов со статусами и
платежами — цена ошибки растёт.

## Варианты
**А.** Оставить как есть. **Б.** Prisma. **В.** Drizzle. **Г.** Голые
SQL-миграции (node-pg-migrate).

## Решение
Вариант **В**, Drizzle 0.45.2.

Prisma тянет отдельный движок и генерацию клиента в сборку — на
Railway это лишний шаг и лишний вес. Drizzle остаётся близко к SQL
(что важно: половина запросов в проекте уже написана руками),
типизирует их и приносит миграции файлами в репозитории.

## Последствия
- Схема описывается в `src/db/schema.ts`, миграции — в `src/db/migrations/`.
- `initDb()` удаляется. Приложение не создаёт таблицы на старте.
- Существующие запросы переводятся **постепенно**: Drizzle умеет
  выполнять сырой SQL, поэтому переход не требует одномоментной
  переписки.
- В CI появляется шаг проверки, что миграции применяются на чистой
  базе.
