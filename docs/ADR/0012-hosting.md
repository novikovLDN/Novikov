# ADR-0012. Railway и Cloudflare остаются

**Статус:** принято, 8 сентября 2026.

## Контекст
Сейчас: Railway (nixpacks, `node .next/standalone/server.js`,
внутренний порт 3000, healthcheck `/`), перед ним Cloudflare.
Замер с европейской точки: TTFB 58–88 мс, отдача статики с
`cache-control: immutable`. Регион один — `cdg1`, Париж. В списке
локаций продукта при этом Сингапур, Япония, ОАЭ.

## Варианты
**А.** Оставить. **Б.** Переехать на платформу с edge-рендерингом.
**В.** Оставить, но вынести витрину на статический хостинг у края.

## Решение
Вариант **А** сейчас, **В** — как план, если замеры из Азии покажут
проблему.

Переезд ради TTFB — это перенос базы, очередей, вебхуков и
переменных окружения, то есть риск для работающей кассы. Витрина
статическая и уже кэшируется Cloudflare у края; динамика (кабинет,
оплата) идёт в Париж, но её открывают после входа, и там ожидания
другие.

## Последствия
- Бюджет TTFB ≤ 400 мс проверяем **из Азии**, а не только из Европы,
  прежде чем считать его выполненным.
- Билд-команда Railway копирует `.next/static` в standalone — при
  изменении структуры сборки её нужно править синхронно.
- Отдельно: у Railway кэшируется `.next` между сборками. На этом
  проекте уже дважды наблюдалась сборка, чей манифест ссылается на
  ненаписанные чанки. Если такое повторится на проде — первым делом
  чистить кэш сборки.
