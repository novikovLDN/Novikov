2. **Senior Web Designer / Creative Director** — визуальная идентичность, композиция, типографика, нарушение сетки, моушн, 3D, ощущение «премиум/миллиардная корпорация».

4. **Product Designer** — продуктовая логика тарифов VPN и VDS, конфигураторы, воронка заказа, биллинг, личный кабинет, edge-cases.
5. **Маркетолог + Копирайтер** — миссия, позиционирование, tone of voice, тексты, которые продают через ощущение и статус, а не «в лоб».

Правила работы агента:

Если рабочая среда не позволяет получить утверждение от человека — фиксируешь план в `/docs/DESIGN_PLAN.md`, проводишь самокритику по чек-листу раздела 11 и только после этого продолжаешь.

- Не выдумываешь факты о компании (даты, цифры, имена). Всё, чего нет в исходных данных, помечаешь как `[TODO: подтвердить у клиента]` и выносишь в список вопросов.
- Не хвалишь свою работу. В отчётах — только что сделано, что осталось, какие риски.

**Компания:** Atlas Secure — технологическая компания, предоставляет:
- VPN-сервис. **Два тарифа. Тарифы не менять, не добавлять, не переименовывать.** Взять состав, цены и лимиты из текущего сайта/кода как есть. Улучшать только подачу.

**Что сохраняем из текущего сайта (клиенту это нравится):**
- Существующие анимации — многие сделаны очень хорошо, необычно и интересно. Их нужно каталогизировать, сохранить (или воспроизвести на новом стеке лучше) и **найти ещё больше таких же нестандартных**.
- Подход к типографике и вёрстке текста: нестандартный, нарушающий «школьные» правила веб-дизайна. Это направление усиливаем.
- Нелинейные композиции. Сайт не должен быть «текст слева, кнопка справа».

**Целевой уровень:** корпоративный сайт миллиардной технологической компании / холдинга. Референсы уровня Selectel, Yandex Cloud, Cloudflare, Vercel, Linear, Stripe, Apple, Hetzner, Mullvad, Tailscale — и **задача превзойти их** по современности, глубине проработки и эффекту погружения.

**Цветовое направление:** максимально светлые оттенки. Светлый корпоративный премиум. Тёмная тема — только как опциональный режим, не основа.

**Эффект:** пользователь заходит и испытывает «вау». Погружение, ощущение масштаба, технологичности, надёжности и статуса. Продажа происходит через стиль, атмосферу, желание и доверие, а не через давление.

## 4. ФАЗА 1 — ГЛУБОКОЕ ИССЛЕДОВАНИЕ

### 4.1 Тренды веб-дизайна и технологий 2027 (обязательно)
Проведи исследование с реальными источниками (Awwwards, FWA, CSS Design Awards, Godly, Siteinspire, Behance/Dribbble только как вторичный сигнал, Figma Config, Chrome/Interop roadmap, W3C CSS WG, отчёты Gartner/Forrester по enterprise UX, дизайн-блоги крупных студий). Ищи не «тренды 2025», а то, что **будет нормой в 2027**: смотри на roadmap браузерных API, на то, что сейчас делают студии уровня Active Theory, Resn, Locomotive, Immersive Garden, Unseen, Lusion, Studio Freight, и на то, что уже внедряют Apple/Stripe/Linear/Vercel.

Минимальный охват тем:
- Типографика: variable fonts, kinetic/reactive typography, текст как основной визуальный объект, крупные кегли, editorial-верстка, наложение, split-text, оптические размеры, кириллица (обязательно проверять качество кириллических начертаний).
- Композиция: нарушение сетки, диагонали, асимметрия, свободные объекты, «сцена» вместо «секций», bento-структуры без клише, слои и глубина, параллакс с физикой.
- Моушн: scroll-driven animations (native CSS `animation-timeline`), View Transitions API (в т.ч. cross-document), Lenis/smooth scroll, GSAP ScrollTrigger/Flip/SplitText, Motion (ex-Framer Motion), spring-physics, cursor-aware эффекты, magnetic-элементы, морфинг SVG, seamless page transitions, loader как часть сторителлинга.
- 3D и WebGL/WebGPU: Three.js/R3F, drei, postprocessing, shader-эффекты (noise, refraction, glass, caustics), WebGPU-fallback стратегия, Spline/Blender-пайплайн, glTF/Draco/KTX2-оптимизация, 3D-визуализация дата-центров, стоек, глобуса сети, потоков трафика, «частицы данных».
- Материалы и свет в светлой теме: мягкие тени, стекло, матовые поверхности, зерно, градиентные сетки (mesh gradients), тонкие металлы, отражения — как сделать премиум на белом без «плоскости».
- Иммерсивность и сторителлинг: scrollytelling, chapter-структура, «путешествие по инфраструктуре», интерактивные схемы, живые данные (latency, uptime, пинг до ближайшего узла).
- Доступность и производительность как часть премиума: `prefers-reduced-motion`, INP, LCP, CLS, Core Web Vitals 2026–2027.
- AI-native UX: умный поиск, персонализация без навязчивости, ассистент выбора сервера (если уместно и не выглядит гиммиком).

### 5.2 Что написать (`02_BRAND.md`)
- Миссия (1 предложение) + расширенная миссия (абзац).
- Видение 2030.

## 6. ФАЗА 3 — ДИЗАЙН-СИСТЕМА И ДИЗАЙН-ПЛАН

Перед началом прочитать skill `frontend-design` и следовать его процессу: план → проверка на «шаблонность» → код → самокритика.

### 6.1 Цвет (светлая палитра)
- База: 4–6 именованных оттенков. Не чистый #FFFFFF как единственный фон — работать с тёплыми/холодными белыми, светло-серыми, «бумажными», «алюминиевыми» тонами, чтобы была глубина.
- Один акцентный цвет, максимум два. Акцент — сдержанный, корпоративный (исследовать: глубокий синий, графит, холодный изумруд, «титановый»). Проверить, чтобы не совпадал с основными конкурентами. Избегать клише: кремовый фон + терракота; чёрный + кислотно-зелёный.
- Материалы: стекло, матовые поверхности, лёгкое зерно, мягкие многослойные тени, mesh-градиенты в светлой гамме. Задокументировать токены теней/blur/зерна.
- Все сочетания проверены на контраст WCAG 2.2 AA (текст) и AAA для основного текста где возможно.

### 6.2 Типографика
- Подобрать 1–2 гарнитуры под статус миллиардной корпорации. Обязательные критерии: отличная кириллица, variable-оси (wght, opsz, желательно wdth), лицензия для коммерческого веба, выразительность в крупных кеглях. Рассмотреть и обосновать выбор среди современных гротесков/нео-гротесков и характерных дисплейных шрифтов (исследовать актуальные релизы 2025–2026 у type-фаундри). Не брать Inter/Roboto/Montserrat по умолчанию.
- Типографическая шкала (модульная), правила line-height, измерение строки < 80 символов, оптические размеры.
- Отдельный раздел «Нарушения правил, которые мы используем намеренно»: наложение текста на объекты, вертикальные строки, разрывы слов как приём, негативный трекинг в дисплейных кеглях, асимметричные абзацы, текст как маска для видео/3D. Каждое нарушение — с правилом, где оно допустимо, а где нет (в тарифах и формах — читаемость превыше всего).
- Запрещено: капслок-эйбровы над каждым блоком, выделение одного слова цветом в каждом заголовке, моноширинный шрифт «для техничности» везде подряд.

### 6.3 Композиция и сетка
- Базовая сетка (12/24 колонок, fluid, container queries) + правила выхода за сетку.
- Каждый экран проектируется как **сцена**, а не как стопка секций. Описать сцены ASCII-вайрфреймами: что главный объект, что вторичное, откуда движение.
- Один «громкий» элемент на экран, остальное — тихое. Правило Шанель: убрать одну деталь перед сдачей.

### 6.4 Моушн-система
- Токены: длительности, easing-кривые (custom cubic-bezier + spring-параметры), правила оркестрации, stagger.
- Один режиссированный момент на страницу (загрузка/hero) + отзывчивый моушн на действия пользователя. Не «fade-up у всего».
- Полная поддержка `prefers-reduced-motion` с осмысленными статичными версиями, а не просто отключением.
- Бюджет: анимации только на transform/opacity/filter, WebGL — с адаптивным качеством, приостановка вне вьюпорта, лимит 60 fps без дропов на среднем ноутбуке и iPhone 13-уровня.

### 6.5 3D и изображения
- Не использовать стоковые фото и стоковые 3D. Все визуальные объекты — авторские: сгенерированные/смоделированные через доступные MCP (image generation, Figma, Spline/Blender-пайплайн если доступны) или процедурные (шейдеры, SVG, CSS).
- Список 3D-сцен к производству: сеть узлов/глобус с реальными локациями, стойка/сервер в разрезе, поток шифрованного трафика, «атлас» как визуальная метафора бренда (карты, слои, меридианы), дата-центр как пространство.
- Пайплайн: модель → оптимизация (Draco, KTX2, инстансинг) → лимит размера на страницу (см. бюджеты) → fallback-изображение/видео.
- Иконки: собственный набор в едином стиле (линия/вес/скругления), не стандартный icon-pack без адаптации.

### 6.6 Figma (если доступен Figma MCP)
Собрать библиотеку: переменные (цвет, типографика, отступы, радиусы, тени), компоненты с вариантами, макеты ключевых экранов (desktop/mobile), прототипы ключевых переходов. Следовать skills `figma-use`, `figma-generate-library`, `figma-generate-design`.

### 6.7 Дизайн-план (`03_DESIGN_PLAN.md`)
Токены + принципы + ASCII-сцены всех экранов + список «что делает этот сайт непохожим ни на кого». Обязательная проверка: «Если бы мне дали похожий бриф без бренда — пришёл бы я к тому же?» Если да — переделать и записать, что изменил.

## 7. ФАЗА 4 — СТЕК, АРХИТЕКТУРА, ИНСТРУМЕНТЫ

Каждый выбор оформить как ADR (`/docs/ADR/000X-*.md`): контекст, варианты, решение, последствия. Перед фиксацией версий — **проверить актуальные стабильные релизы на дату выполнения**; ниже — ориентир, не догма.

### 7.1 Рекомендуемый стек (проверить актуальность)
- **Фреймворк:** Next.js (App Router, RSC, Server Actions, PPR/streaming), TypeScript strict. Альтернатива для обоснования — Astro + islands, если аналитика покажет преимущество по производительности маркетинговых страниц. Выбрать одно и обосновать.
- **Стили:** Tailwind CSS v4 (CSS-first конфиг, `@theme`) + CSS-переменные дизайн-токенов; container queries; native scroll-driven animations где возможно.
- **Компоненты:** Radix Primitives / shadcn как базис доступности, но с полной визуальной переработкой под дизайн-систему (не должно быть узнаваемого «shadcn-look»).
- **Моушн:** GSAP (ScrollTrigger, Flip, SplitText, MorphSVG при наличии лицензии) + Motion для React-компонентов + Lenis. View Transitions API для переходов страниц.
- **3D:** Three.js + React Three Fiber + drei + postprocessing; WebGPU-рендерер с WebGL-fallback; сцены лениво загружаются.
- **Контент:** headless CMS (Payload / Sanity — обосновать) для блога, документации, статус-новостей, команды. Тарифы VPN — из источника истины, редактируемые через CMS/конфиг с валидацией Zod.
- **Формы/валидация:** react-hook-form + Zod; серверная валидация обязательна.
- **Состояние:** серверное по умолчанию; клиентское — минимально (Zustand/Jotai для конфигуратора).
- **i18n:** next-intl (ru/en), маршруты с локалями, hreflang.
- **Платежи:** провайдер(ы) по юрисдикции клиента `[TODO: уточнить]` — карта (Stripe/локальный эквайринг), криптовалюта (для VPN/серверов — типично), инвойс для юрлиц. Абстракция `PaymentProvider` с адаптерами.
- **Авторизация/кабинет:** Auth.js или существующая система клиента; magic-link + 2FA.
- **Backend для VDS:** API-слой (route handlers / отдельный сервис), очередь задач (BullMQ/Redis) для провижининга, webhooks от платёжки, статусы заказа. Интеграция с реальным провижинингом ДЦ — через адаптер, стаб в dev.
- **База данных:** PostgreSQL + Prisma/Drizzle; миграции в репозитории.
- **Аналитика:** приватная (Plausible/Umami/PostHog self-hosted) — соответствует бренду приватности. Cookie-баннер минимальный и честный.
- **Инфраструктура:** Docker, IaC (Terraform/Pulumi — минимально для окружений), CI/CD (GitHub Actions): lint → typecheck → unit → e2e → Lighthouse CI → build → preview → prod. Превью на каждый PR. CDN + edge-кэш. Security headers, CSP (nonce для скриптов), HSTS, rate-limit на формы и API.
- **Наблюдаемость:** Sentry (или self-hosted аналог), логирование, uptime-мониторинг, публичная статус-страница (часть бренда доверия).

### 7.2 Качество кода — обязательные инструменты
- ESLint (strict, `eslint-plugin-react-hooks`, `jsx-a11y`, `import/order`, `@typescript-eslint` strict-type-checked) или Biome — выбрать один, обосновать.
- Prettier (если не Biome), EditorConfig, Husky + lint-staged, commitlint (Conventional Commits).
- Vitest + Testing Library для unit/компонентов; Playwright для e2e (ключевые потоки: подключение VPN-тарифа, сборка и оплата VDS, смена языка, формы поддержки); Storybook (или Ladle) для компонентов с визуальными регрессиями (Chromatic/Playwright screenshots).
- Lighthouse CI с бюджетами; axe-core в e2e; Knip/depcheck для мёртвого кода; bundle-analyzer.
- Структура: feature-sliced или доменные модули (`/features/vpn`, `/features/vds`, `/features/billing`, `/ui`, `/motion`, `/three`), запрет циклических импортов, публичные API модулей через `index.ts`.

### 7.3 MCP и скиллы, которые использовать (по доступности)
- `frontend-design` — обязательно перед дизайном и кодом UI.
- Figma MCP (`figma-use`, `figma-generate-library`, `figma-generate-design`, `figma-generate-diagram`) — библиотека, макеты, диаграммы архитектуры и потоков заказа.
- Playwright/Browser MCP — скриншоты каждого экрана на 3 брейкпоинтах, визуальная самопроверка, аудит анимаций.
- Документационные MCP (Context7 или аналог) — актуальные API Next.js/GSAP/R3F/Tailwind вместо памяти.
- Image/3D-generation MCP (если есть) — авторские визуалы; иначе процедурная графика.
- GitHub MCP — PR, issues, CI-статусы.
- Web search — исследование, цены, релизы.
Если какой-то MCP недоступен — зафиксировать в `ASSUMPTIONS.md` и предложить ручной путь.

### 7.4 Бюджеты производительности (жёсткие)
- LCP ≤ 2.0 s (mobile, 4G), INP ≤ 150 ms, CLS ≤ 0.05, TTFB ≤ 400 ms.
- JS на первой загрузке (без 3D) ≤ 180 KB gz; 3D-сцены — лениво, суммарно ≤ 2.5 MB на страницу с прогрессивной загрузкой и LOD.
- Шрифты: subset (latin + cyrillic), `font-display: optional/swap` по контексту, preload критических.
- Изображения: AVIF/WebP, responsive `sizes`, blur-placeholder.
- Lighthouse ≥ 95 по Performance/Accessibility/Best Practices/SEO на всех ключевых страницах (mobile и desktop).

## 8. ФАЗА 5 — СПЕЦИФИКАЦИЯ ЭКРАНОВ

Для **каждого** экрана: цель, сцена (ASCII-вайрфрейм), главный объект, моушн-сценарий (что происходит при загрузке, при скролле, при действии), состояния, адаптивность (desktop / tablet / mobile / reduced-motion / low-end), тексты (ссылка на `02_COPY.md`), SEO, метрики. Ни один экран не должен быть «текст слева — кнопка справа».

### 8.1 Главная
- Hero — режиссированный момент: авторская 3D/шейдерная сцена (сеть/атлас/поток) в светлой гамме, типографика как объект, минимум текста, один спокойный CTA. Загрузчик — часть истории, не спиннер.
- «Кто мы» — не список преимуществ, а короткая история масштаба: инфраструктура, узлы, принципы. Живые данные (число узлов, локации, средний пинг) — только реальные или `[TODO]`.
- Продукты: VPN (два тарифа, кратко) и Серверы (линейка от $300) — как две «двери», каждая со своим визуальным характером.
- Инфраструктура/дата-центры — иммерсивный блок (scrollytelling или 3D-проход).
- Доверие: принципы приватности, прозрачность, статус, юрисдикция.
- Финальный блок — приглашение, а не «купи сейчас».

### 8.2 VPN — страница продукта
- Два тарифа **как есть**. Сравнение — визуально сильное, читаемое, без «самый популярный» ярлыков-давления (допустимо спокойное «выбирают чаще» только если есть данные).
- Объяснение технологий (протоколы, шифрование, no-logs, kill switch, устройства) через интерактивные схемы, а не иконки-списки.
- Приложения/платформы: реальные ссылки `[TODO]`.
- Поток подключения: выбор тарифа → аккаунт → оплата → инструкции. Все состояния.

### 8.3 Серверы (VDS/dedicated)
- Обзор линейки от $300 с честным описанием (см. раздел 9).
- Конфигуратор: базовая конфигурация → опции (диски, RAM, порт, трафик, DDoS, IP, ОС, панель, бэкапы, локация) → живой расчёт цены → итог.
- Страница каждой конфигурации: спецификация в структурированном виде (таблица, которая красиво читается, а не «Excel»), что входит, SLA, сроки, FAQ.

- Миссия, видение, ценности, история (реальная `[TODO]`), команда (реальная `[TODO]`), ответственность и прозрачность. Издательская верстка, крупная типографика, авторские визуалы.

### 8.5 Инфраструктура / Дата-центры / Технологии
- Отдельная иммерсивная страница: как устроена сеть, уровни защиты, оборудование, резервирование, мониторинг. Интерактивные разрезы, схемы, живые метрики.

### 8.6 Безопасность и приватность
- Политики, аудит, no-logs, юрисдикция, bug bounty (если есть), контакты security-команды, PGP.

### 8.7 Документация / База знаний / Блог

### 8.8 Статус-страница

### 8.9 Поддержка / Контакты

### 8.10 Личный кабинет

## 9. ФАЗА 6 — ПРОДУКТОВАЯ ЛОГИКА VDS: ЛИНЕЙКА, ЗАКАЗ, ОПЛАТА

### 9.1 Линейка (пример структуры — заполнить по результатам `01_VDS_MARKET.md`)
Для каждой конфигурации: имя (единая номенклатура, например по географии атласа или по слоям), CPU, RAM, диски/RAID, порт, гарантированная полоса, трафик (безлимит/лимит/95th), DDoS, IPv4/IPv6, локации, IPMI, SLA, срок выдачи, цена/мес, установка, минимальный срок, скидки за 3/6/12 мес (сдержанные, без «−70%»).
Минимальный старт — **$300/мес**. Верхняя граница — по рынку. Обязательно: честные примечания о fair use и о том, что именно гарантируется.

### 9.2 Опции
Дополнительные диски, RAM, апгрейд порта (10G/25G), расширение трафика, продвинутая DDoS-защита, дополнительные IP/подсети, приватная сеть, бэкапы, панель управления, ОС/образы, управляемое администрирование, установка ПО. Для каждой — цена, единица, ограничения совместимости.

### 9.3 Конфигуратор
- Правила совместимости (например, 25G только в определённых локациях), валидация на клиенте и сервере (одна Zod-схема).
- Живая цена: ежемесячно, разово, итог с налогом по юрисдикции `[TODO]`.
- Сохранение конфигурации по ссылке, сравнение конфигураций.

### 9.4 Поток заказа
1. Конфигурация → 2. Аккаунт (вход/регистрация, юр/физлицо, реквизиты) → 3. Срок и метод оплаты → 4. Проверка и оферта → 5. Оплата → 6. Ожидание провижининга (страница со статусом и ETA) → 7. Готово: реквизиты доступа, IPMI, инструкции.
Статусы заказа: `draft → pending_payment → paid → provisioning → active → suspended → cancelled → failed`. Каждый статус — своя страница/письмо. Идемпотентные webhooks. Возвраты и споры — процесс описан.

### 9.5 Оплата
- Методы: карта, крипто, инвойс для юрлиц; рекуррентные списания, авто-продление с уведомлением за N дней, grace period, приостановка, восстановление.
- Безопасность: не хранить карточные данные, PCI через провайдера, 3DS, антифрод, лимиты.
- Письма/уведомления: заказ, оплата, провижининг, готовность, продление, проблемы — тексты в tone of voice.

### 9.6 Тесты
- Unit: расчёт цены, совместимость опций, переходы статусов.
- E2E: полный заказ с моком платёжки; отказ оплаты; повтор webhook; отмена.

## 15. ЖЁСТКИЕ ЗАПРЕТЫ (сводно)

1. Менять состав, цены или количество тарифов VPN.
2. Стоковые фото, стоковые 3D, стоковые Lottie, шаблонные UI-киты без переработки.
3. Композиция «текст слева — кнопка справа» и любые шаблонные лендинговые блоки.
4. Продажа «в лоб»: таймеры, ложная срочность, кричащие скидки, навязчивые попапы, «№1», «лучший».
5. Выдуманные факты: имена сотрудников, цифры uptime, количество клиентов, сертификаты.
6. Тёмная тема как основа.
7. Fade-up на каждой секции и одинаковые hover-эффекты у всех карточек.
8. Игнорирование reduced-motion, доступности и бюджетов производительности.
9. Переход к коду без утверждённого (или самокритикованного) дизайн-плана.
10. Использование API библиотек «по памяти» вместо проверки актуальной документации.
